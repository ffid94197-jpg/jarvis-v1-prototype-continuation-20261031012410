# Prototype JARVIS — recovered internet component harvest and integration closure matrix

**As of 2026-11-03.** This is the authoritative disposition register for the recovered research inventories and the November 3 seven-project shortlist. It distinguishes *research reviewed*, *useful behavior adapted*, *upstream source installed*, and *runtime acceptance*. These are not interchangeable.

## Non-negotiable integration architecture

- One JARVIS Core owns goals, planning, state, retries, scheduling and completion claims.
- Guardian remains the only authority for side effects, approvals, scope, identity and audit.
- LAYA remains advisory model routing only.
- Windows Companion, browser, voice, vision, Minecraft, memory and external connectors are bounded native subsystems.
- No imported project may introduce a competing agent identity, independent shell, bypass, self-approval, direct machine-control route or unjournaled side effect.
- Use cleanly licensed and pinned source; preserve attribution and license files. Model weights and their terms are reviewed separately from code.
- Dispositions: KEEP = already the correct native foundation; WRAP = call the capability through JARVIS-owned contracts; HYBRID = adapt the valuable behavior, do not import the full runtime; REFERENCE-ONLY = architecture/evaluation only; DEFER = wait for prerequisites/benchmark; REJECT = conflicts with owner choices or adds risk without sufficient benefit.

## Completion vocabulary

- **Research reviewed**: source, license and purpose were inspected.
- **Disposition assigned**: KEEP/WRAP/HYBRID/REFERENCE-ONLY/DEFER/REJECT is explicit.
- **Native implementation merged**: code is on main under JARVIS-owned contracts.
- **Offline contract passed**: specific deterministic test evidence exists.
- **Live accepted**: real owner Windows environment, model weights, permissions and end-to-end task were exercised.
- **Release accepted**: all mandatory V1 release gates passed.

A row cannot advance to a stronger state based on documentation, a mocked test, an upstream benchmark, or a successful GitHub merge alone.
