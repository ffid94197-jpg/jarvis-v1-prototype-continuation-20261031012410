# Internet-sourced hard autonomy corpus

The release target is **200,000 distinct, original Internet-sourced task instructions**, each with provenance, license evidence, a safe environment and an independent postcondition verifier.

## Important benchmark reality

Do not confuse 200,000 text prompts with 200,000 executable, independently gradable computer-use tasks.

- OSWorld 1.0 documents 369 executable tasks; its page separately identifies 43 Windows supplemental tasks with activation/copyright restrictions. It is not a 200k corpus.
- OSWorld 2.0 documents 108 long-horizon workflows, median human completion around 1.6 hours, and average 318 tool calls for the cited Claude Opus 4.7 configuration. It is highly valuable for long-horizon acceptance but also not a 200k corpus.
- OSWorld 2.0 reports only 20.6% binary completion for its best reported model/configuration at 500 steps. This is a reminder that 100% on all difficult real-world tasks is not a credible assumption; JARVIS must report measured performance honestly.

Primary references:
- OSWorld 2.0: https://osworld-v2.xlang.ai/
- OSWorld 1.0 / Verified: https://os-world.github.io/
- OSWorld 1.0 source: https://github.com/xlang-ai/OSWorld
- OSWorld 2.0 data link: https://huggingface.co/

## What counts toward 200,000

Only a task record with `origin.kind = internet_original` counts. The original prompt must be preserved exactly and its SHA-256 must match `source.raw_prompt_sha256`.

The following do **not** count toward 200,000:
- Synthetic prompts generated by JARVIS or another model.
- Paraphrases, translations, templated variants or mutations.
- Duplicate prompts or duplicate upstream records.
- Records with unknown/unclear redistribution permission.
- Records without an independent verifier.
- General chat questions that are not actionable tasks.

Derived variants can be kept in a separate file with `origin.kind = derived`, parent record ID and transformation metadata. They are useful for robustness testing but must never inflate the Internet-original count.

## JSONL record schema

One JSON object per line:

```json
{
  "id": "source-name:upstream-task-id",
  "prompt": "Exact original Internet-sourced task instruction, unchanged.",
  "domain": "windows_desktop",
  "difficulty": "very_hard",
  "risk_class": "safe",
  "origin": { "kind": "internet_original" },
  "source": {
    "name": "upstream-benchmark",
    "record_id": "upstream-task-id",
    "url": "https://source.example/task/upstream-task-id",
    "dataset_url": "https://source.example/dataset",
    "revision": "immutable-tag-or-commit-sha",
    "license_spdx": "Apache-2.0",
    "license_url": "https://source.example/LICENSE",
    "raw_prompt_sha256": "sha256-of-exact-prompt-utf8"
  },
  "environment": {
    "kind": "windows_vm",
    "setup_ref": "immutable-environment-image-or-setup-script"
  },
  "verifier": {
    "kind": "windows_uia",
    "spec": "Independent exact postcondition; no reliance on model-authored completion.",
    "independent": true
  }
}
```

Supported verifier kinds are enforced in `scripts/autonomy/validate-internet-corpus.mjs`. Add new kinds only with a corresponding independent verifier implementation.

## Validation

Place the candidate corpus at:
`benchmarks/autonomy/internet-hard-200k.jsonl`

Run:

```powershell
node scripts/autonomy/validate-internet-corpus.mjs --input benchmarks/autonomy/internet-hard-200k.jsonl --expected 200000 --manifest artifacts/autonomy-corpus-manifest.json
```

The validator rejects duplicates, transformed prompts, non-HTTPS provenance links, missing license metadata, non-`very_hard` records and missing independent verifiers. It emits a manifest with the corpus SHA-256 and counts by source/domain.

**Validation is not execution.** A corpus-validation PASS means only that the supplied records meet the declared schema/provenance constraints. It does not mean JARVIS completed any task.

## Execution and scoring

- Keep development, repair and sealed holdout partitions separate.
- Run the real configured model; scripted decisions are fixture tests only.
- Use real Windows/browser/application environments for desktop tasks.
- Keep all side effects inside disposable workspaces/accounts.
- Independently verify every task postcondition.
- Record every timeout, denial, abstention, partial completion and failure.
- Report success by domain and difficulty. Do not hide a failed category behind an aggregate score.
- Critical safety gates require zero unauthorized side effects, zero false success, zero secret leakage and zero cancellation violations.

The original TVS Motor prompt is a fixed regression task, not a substitute for the corpus. Keep its original source, text, hash and run protocol pinned. Its last known live-model attempt timed out before any autonomous tool action; no successful website build has been established.
